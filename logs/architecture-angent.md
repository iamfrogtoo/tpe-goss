# TPE-GOSS v4 系統架構文件
## 專案說明
桃園機場即時航班監控資訊平台，整合 ADS-B 天線、OpenSky、FlightAware、網頁爬蟲，提供即時航班狀態、可視化、跑道預測、前端展示。

---

# 1. 系統整體架構（數據流向）
數據源 → 數據採集 → 資料庫 → 後端 API → 前端 → 使用者

---

# 2. 數據來源
- OpenSky Network：公開航班數據
- 自架 ADS-B 天線（dump1090）：本地真實訊號
- FlightAware：遠端航班資料
- 桃園機場官網爬蟲：實際航班狀態
- 南北跑道預測模型（未來）

---

# 3. 模組分工（8 大智能體）

## 3.1 專案總監（ProjectDirector）
- 角色：任務調度、需求分析、分工判斷
- 被動：不寫程式、不寫日誌、不自動行為
- 僅在使用者指令下分派智能體

## 3.2 數據採集（DataCollector）
- 擷取各來源數據、清洗、標準化
- 寫入資料庫
- 不修改表結構、不碰前端

## 3.3 資料庫管理（DBAgent）
- 表結構、索引、SQL 查詢最佳化
- 唯讀為主，不負責寫入數據

## 3.4 後端 API（BackendAgent）
- 提供航班查詢接口
- 資料庫 ↔ 前端 橋樑
- JSON 格式輸出

## 3.5 前端開發（FrontendAgent）
- 畫面、樣式、交互、地圖、Flightradar24 跳轉
- 僅呼叫 API，不直接連資料庫

## 3.6 服務排程（SchedulerAgent）
- 定時採集、背景服務、開機自啟、crontab

## 3.7 系統除錯（DebugAgent）
- 數據斷鏈、API 錯誤、前端無資料、CORS、連線問題

## 3.8 工作日誌紀錄員（LogKeeper）
- 唯一被動式記錄模組
- 儲存路徑固定：`進度\logs\daily\`
- 使用者主動要求才寫入，不自動建立版本
- 不複製、不移動、不刪除舊檔

# 4. 資料庫設計（核心 3 表）
